# 06 — Art Direction, Assets, Build Plan

## Art direction

Derived from the supplied reference set: **neon glass and polished metal over deep
violet**, translated from a flat UI look into a lit 3D one.

| Token | Value | Use |
|---|---|---|
| Void | `#0B0418` → `#1A0B33` | skybox gradient, world shell |
| Primary neon | `#B44BFF` | track edge emission, primary UI |
| Secondary neon | `#2E7BFF` | boost surfaces, checkpoint gates |
| Gold | `#FFC24B` | cores, stars, goal gate |
| Alarm | `#FF3D6E` | forbidden volumes, red ghost, decay wave |
| Cold | `#4BE3FF` | Magnetite polarity, brake surfaces |

**The track is the light source.** Levels are dark volumes; the ribbon you build is what
illuminates them. This is a direct consequence of the design — the player literally lights
their own way — and it means level geometry needs almost no baked lighting, which is a
large performance and authoring win.

**Piece class reads as colour on the ribbon edge:**
Straight = violet · Turn = blue · Vertical = cyan · Roll = magenta · Air = gold ·
Surface = per-effect (boost blue, brake cold, rumble amber) · Structural = white.
A player glancing back at their own track can read what they built.

**The letter R.** The reference glyph is Revolut's registered mark and cannot be used.
The Ravelane mark is an original letterform: an **R whose leg is a length of track ribbon**
that peels away from the bowl — the logo is the game's verb. Same glass-and-neon
treatment, same palette, different letterform.

## Asset budget

| Category | Count | Format | Tool |
|---|---|---|---|
| Piece meshes | 40 | procedural — generated by Core, not authored | *none* |
| Car models | 12 | USDZ, low-poly, ~3k tris | `mcp__meshy-3d` |
| Core / gate / checkpoint props | 6 | USDZ | meshy |
| Hazard props | 8 | USDZ | meshy |
| Piece cards (UI icons) | 40 | 512² transparent | `mcp__openai-image__generate_image` |
| Part icons | 30 | 256² transparent | openai |
| World key art / select cards | 6 | 1024×1536 | openai |
| Skybox panoramas | 6 | 2048×1024 equirect | openai |
| UI chrome, buttons, frames | 12 | 1024² / 1024×576 | openai |
| Logo mark + wordmark | 2 | 1024² transparent | openai |
| App icon | 1 | 1024² opaque | openai |
| **Total generated** | **123** | | |

**Track geometry is never an authored asset.** All 40 pieces are described by numbers in
`pieces.json` and turned into ribbon by `RavelaneCore`. That is 40 models the project never
has to make, never has to keep in sync with the physics, and never has to re-export when a
piece is retuned. It is the largest single saving in the plan.

3D generation is confined to the 26 props that actually need to be objects. Everything
else is either procedural or 2D UI.

### Generation strategy

- One prompt template per family so a family looks like a family; templates kept in
  `design/art-prompts.md` so the whole set is reproducible and a reskin is one script run.
- Batches of 5–8 parallel calls, transparent backgrounds for icons.
- Post-process on Linux: alpha trim, canvas normalise, contact-sheet render so all 40
  piece cards can be judged for legibility side by side rather than one at a time.

## Build plan

Ordered so everything blocked on the Mac comes as late as possible.

### M0 — Math foundations *(Linux)*
`Fixed` Q32.32, CORDIC trig, `Vec3`, `Quat`, `Transform3`, arc-length spline with
parallel-transport frames, `SplitMix64`. Full test coverage including
cross-architecture determinism fixtures.

### M1 — Track engine *(Linux)*
`Piece`, catalog loading, `TrackChain`, socket composition, ribbon sampling, spatial-hash
clearance, self-intersection. Fixture levels. **`RavelaneCLI render --svg` lands here** so
tracks become reviewable without a renderer.

### M2 — Simulation *(Linux)*
Fixed-step integrator, grip model, banking, sliding, ballistics and landing tolerance,
the three clocks, objectives, scoring. Golden replays that must reproduce bit-exactly.

### M3 — Play systems *(Linux)*
Deck, hand, draw model, discard, parts, cars, world rulesets (gravity/decay/fog),
hazards, junctions.

### M4 — Content *(Linux)*
40 pieces, 12 cars, 30 parts, 60 levels across 6 worlds. Every level gets a solver-verified
stored solution. Validator green.

### M5 — Balance *(Linux)*
`RavelaneCLI sweep` across archetypes × levels. Retune par counts, target times, piece
costs and Material yields until each archetype has a path and the star curve matches
intent.

### M6 — First pixels *(Mac — the first time a Mac is needed)*
`xcodegen`, iOS target, RealityKit scene, `LowLevelMesh` ribbon builder, chase camera,
one playable Foundry level.

### M7 — Full shell *(Mac)*
Deck builder, level select, results, settings, unlock flow, onboarding.

### M8 — Feel *(Mac)*
Engine synthesis, grip audio, runway heartbeat, haptics, particles, camera polish,
reduce-motion and assist modes.

### M9 — Ship
Device testing across iPhone 12 → 17, TestFlight, App Store Connect. Rating is expected to
be 4+ — there is no gambling, violence, or user-generated content in this design.

**M0–M5 is roughly 70 % of the total work and runs entirely on the Linux box.** The Mac
becomes necessary at M6.
